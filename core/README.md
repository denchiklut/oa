# Core (`//oa`)

The engine side of Oa, built inside the Chromium tree as `//oa`. `scripts/build.sh` links this directory into the
checkout as `src/oa` and `chromium/patches` links the target into Chromium's framework.

| Path | Layer | Holds |
| --- | --- | --- |
| `app/engine.mm` | Chromium | The browser process: the app's `NSApplication`, the `ChromeMainDelegate` subclass that runs the app's ready callback between Chromium's initialization and its run loop, the embedder factories, and quitting |
| `browser/` | Chromium | C++ against Chromium internals: a `Browser` per (window, profile) with no Chrome views (`window_browser`, `ui/browser_window_impl`), pages as `//chrome` tabs (`page_impl`), profiles loaded by app UUID (`profile_services`), extensions through Chrome's own system with the app's views in place of Chrome's (`extensions_impl`, `ui/extensions_container_impl`, `ui/extension_dialogs_impl`), a page's picture-in-picture video in a view the app hosts (`ui/video_overlay_window_impl`). `forwarding_web_contents_delegate.*` is generated by `scripts/generate_forwarding_delegate.py`; rerun it after a Chromium update |
| `public/` | Core | The C++ interface between `objc/` and `browser/`, with no Chromium headers |
| `objc/OACore.h` | Core | The exported Objective-C API: `OACoreMain`, `OAEngine`, `OAProfile`, `OABrowser`, `OAPage`, `OAPageDelegate`. `devkit/Sources/DevKitLive/OACore.swift` mirrors it; keep both in step |

Every call happens on the main thread, which is Chromium's UI thread.
